## 洞天试作口径

本轮已经询问四向道路、缺料与分料顺序是否调整，尚未收到新的规则决定。以下先用于最小闭环，正式规则仍可在试玩后修改。

### 配置与数值

| 字段或内容 | 当前值与用途 |
|---|---|
| width / height | 8 / 6；坐标从左上角 (0, 0) 开始 |
| entrance / initial_roads | 入口 (0, 3)，其右侧五格为初始路；调整时需保持在地块内 |
| buildings | 稳定 ID 到建筑定义；name、category、size、costs、worker_slots、recipes 等 |
| categories | housing 民居、production 生产、manufacturing 制造、landscape 景观 |
| items.json items.category | resource 基础资源、herb 药材、product 制品；药材不归入基础资源 |
| recipes.json recipes | inputs 与 outputs 为物品 ID 到正整数数量；空 inputs 表示不耗材料，每栋每回合执行一批 |
| buildings.*.recipes | 建筑菜单中的配方 ID 列表，引用独立配方表 |
| buildings.*.output_categories | 有任务的建筑必填，约束全部产物；灵田为 herb，林场采石场为 resource，丹炉为 product |
| workers | 御灵 ID、名称与各 work_type 的适应性；默认青禾、玄砂 |
| 适应性映射 | 一只御灵倍率 = 1 + 适应性 / 100；多只分别相乘，未派工倍率为 1 |
| bonus | affix 同词条归组；work_types 决定适用建筑；peak 相邻满额加成；radius 衰减范围 |
| distance_metric | manhattan 为曼哈顿距离，可改 chebyshev；取两建筑占地格之间的最近距离 |
| output_rounding | floor，逐建筑逐物品向下取整；可改 round |

默认示例配方：灵田选择产 4 清心草或 4 青蕴草，林场产 4 木，采石场产 4 石，丹炉消耗 4 清心草产 2 清心丹。青蕴草尚无正式加工用途，不自动采纳通用辅材提案。实际产出再乘御灵、景观倍率，材料成本不随倍率增加。竹舍容量 2；所有试作生产建筑为一个工作槽，尚无中大型内容，但规则与界面支持 2/3 槽。

景观贡献计算：`peak * max(0, 1 - (最近距离 - 1) / radius)`。相邻距离 1 满额；距离达到 `radius + 1` 时为零。相同 affix 的贡献先相加，再以 `1 + 合计贡献` 形成该乘区，不同词条之间相乘。

例如灵田基础 4，青禾适应性 50，两座相邻稻草人各加丰收 0.5，一座相邻灵泉加灵气 0.25：`4 * 1.5 * (1 + 0.5 + 0.5) * (1 + 0.25) = 15`。

### 管理与生产

- 上下左右相连且能到入口的道路才有效，斜角不算。民居、生产与制造建筑至少一个占地格邻接有效道路；景观不需要道路。
- 可以预先建在未连通处，但生产停工，民居不提供容量。无施工等待，当回合连通并安排任务即可生产。
- 派工时自动视为入住，取消工作即回待命池；暂不做单独入住界面。这是对正式“收藏与入住分开”的临时简化。
- 移动或断路若使民居容量低于已分配御灵数，整次操作拒绝，需先取消部分派工。不会自动驱逐或偷偷取消工作。
- 建筑、道路不消耗自由精力或培养槽。道路与移动免费；没有拆除、退款、卖出、旋转和拖拽施工。
- 建筑 ID 创建后不变；移动保留 ID、任务和御灵，任务跨回合保留。未派御灵但已经选配方的建筑仍按基础产出，不计入“未安排”提醒。
- 培养先扣自己的材料。生产阶段再按建筑 ID 从小到大分配已有库存；缺料整单停产，不部分扣费，也不保留材料给下一回合。
- 预览使用同一 forecast 函数，并先减去日程草稿的材料成本。预览不扣费、不锁库存；建造、服药、调整日程后会重新计算。
- 分配投入时只减预算，不加入任何本批产出。全部计算后统一扣料、统一入库，避免同批加工链。尚未接入入库后的剧情升级检查。
- 确认日程前提示未安排生产的建筑；确认仍然结算才会推进。结果页禁止管理及消耗物品，下一回合恢复操作。
