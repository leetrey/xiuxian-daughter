# 山河养成录 · Godot 原型

> 当前实现：D1 培养回合 + D2 洞天最小生产闭环；D3 已接入对话、完成记录、物品结算和活动解锁。设计入口见 [设计文档索引](docs/README.md)，实现范围与试算选择见 [开发进度](docs/05-development-progress.md)。
> 文档从 [当前设计入口](docs/README.md) 按需阅读；历史方案集中归档，不作为默认开发上下文。

当前可以操作：

- 默认三个培养槽：选择活动、调整顺序、清空、确认。
- 自由活动单独扣精力，培养不扣精力；清心草按库存消耗并减压。
- 16 项永久属性与四维汇总，每项培养按执行前压力判定大成功、成功、失败。
- 确认后展示逐项成长，再进入下一回合；精力恢复，压力保留。
- 内部采用 60 回合、12/24/24 阶段基线；中后期开放额外吐纳，不显示具体年龄年月。
- 家园场景与三阶段立绘；属性、自由活动、日程和成长札记按需展开，不显示具体年龄年月。
- 洞天场景：等距地块中放置、移动建筑，增删道路，选中建筑后设置任务、御灵并查看预计投入产出。
- 灵田按配置选择清心草或青蕴草；清心草下回合可投入丹炉加工，产物按真实库存消耗，为培养减压。
- 民居容量、道路连通、御灵适应性和距离衰减景观参与生产；未安排生产时在确认前提示。
- 回合始末按主线、支线顺序播放符合条件的剧情；最后一句确认后才完成节点并提交物品变化、活动解锁。

洞天目前直接开放 8×6 地块、七种建筑与两只御灵，仅用于验证经营，不代表剧情解锁已实现。缺料整单停产、按建造 ID 分料、四向道路等是待确认的试作规则。

剧情已接入游戏内播放，条件、前置、三阶段表现、物品费用与奖励均可配置。土地、图纸、父亲恢复与继承免扣费尚未接入；冒险、战斗、存档、继承选择、正式结局和小游戏仍未实现。A/B 仅实现计算口径，未实现换装界面。关闭程序会丢失本次试玩进度。

## 试玩闭环

开局先出现“草木闲话”示例，点右下角箭头读完后进入自由操作。永久属性总和超过示例门槛 1000 时，会在下一剧情检查点播放“灵息初成”，读完获得示例奖励 1 颗清心丹。文本、门槛与奖励都不是正式定案。

1. 打开“洞天”，从列表选灵田，在初始道路旁放置；右侧选择“种植清心草”。
2. 建造竹舍后，可在灵田的工作槽选择御灵。没有御灵也有基础产出。
3. 点左上角家园图标返回“山居”，从右下角“安排日程”进入培养。确认后统一生产入库。
4. 下一回合可直接服用清心草减压；也可建丹炉、选择炼制清心丹，使用已有草加工。
5. 丹药在结算后入库，下一回合可服用。同一次结算中新长出的草不能立刻被丹炉使用。

移动先选建筑，再切“移动”点击空位；“道路”模式点击空格添加道路、点击已有道路移除；右键返回选择模式。当前没有拆除或卖出功能，布局可以免费移动。

点击女儿或“人物详情”查看细分属性；底部“自由活动”可拜访或使用减压物品。菜单可关闭后继续查看场景，不会自动执行日程；结算后从“成长札记”进入下一回合。新场景和立绘为可替换的视觉样例，素材格式与来源见 [assets/README.md](assets/README.md)。

## 修改配置

作者从 [内容填写指南](docs/06-content-authoring.md) 开始；程序提供通用框架和少量例子，具体药材、丹方、数值与文案由作者填写。

- [items.json](data/items.json)：物品名称、分类与描述。
- [recipes.json](data/recipes.json)：种植、采集、加工的投入产出。
- [cave.json](data/cave.json)：建筑、可用配方 ID、允许产物分类、御灵、景观与地块。
- [cultivation.json](data/cultivation.json)：活动、使用物品的效果、初始库存及培养规则。
- [story.json](data/story.json)：剧情条件、前置、三阶段文本/立绘、物品费用、奖励与活动解锁。

修改后重新启动游戏加载；目前没有热更新或配置编辑器。作者只检查配置时运行下方命令，不依赖冒烟测试中的固定示例数值：

```bash
godot --headless --path "/Users/leet/WorkBuddy/独立" res://scenes/validate_content.tscn
```

成功输出 `CONTENT_CONFIG_OK`；填错物品引用、配方数量或灵田产物分类时会报告位置。字段及试作口径见 [开发进度](docs/05-development-progress.md)。

检查剧情的开局条件并打印三阶段文本，可在上方命令末尾加 `-- --story-preview`。终端预览仍为只读，不会扣费、发奖或完成剧情，填写说明见 [内容填写指南第 7 节](docs/06-content-authoring.md#7-剧情条件表现与奖励)。

培养槽可设为 3 至 5，目前是开发调试入口，不是已经完成的成就继承功能。留空、重复、取整等试作选择不替代 GDD 中的待确认项。

## 推荐阅读顺序

1. [cultivation.json](data/cultivation.json)：查看试算规则与活动定义。
2. [game_state.gd](scripts/game_state.gd)：配置读取、本局状态、A/B 与回合推进。
3. [schedule_manager.gd](scripts/schedule_manager.gd)：日程校验、压力判定与实际结算。
4. [cave_rules.gd](scripts/cave_rules.gd)：放置、道路、派工、乘区与批次生产。
5. [main.gd](scripts/main.gd)：家园、立绘、浮层菜单、闲置确认、结算与回合按钮。
6. [cave_ui.gd](scripts/cave_ui.gd) 与 [cave_board.gd](scripts/cave_board.gd)：洞天操作、选中详情、等距投影与建筑图集。
7. [smoke_test.gd](scripts/smoke_test.gd)：核心行为的验证与真实窗口截图。

调用链：回合开始剧情 -> `assign_slot()` 修改草稿 -> `confirm_schedule()` 执行培养 -> `Cave.settle()` 生产入库 -> 回合末剧情 -> 札记 -> `advance_turn()` 开启下一回合。剧情调用链见 `story_flow.gd` 与开发手册。
